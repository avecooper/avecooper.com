# Agent guidance

Work within the current issue and its authorized files and actions. Preserve the
settled two-page structure, visual system, narrative, evidence, and accepted
interaction behavior described in [maintenance guidance](docs/maintenance.md).
Future explicitly approved work may change these requirements.

Inspect only files and sources necessary for the task and authorized in the
session. Owner-maintained planning and synthetic evidence outside this repository
are not blanket permission to inspect neighboring archives, raw captures, private
career records, or production Job Radar sources.

Keep private sources, raw captures, credentials, environment secrets, local absolute
paths, and production data out of this public repository. Use repository-relative
paths and safe descriptions of external sources in documentation.

Use validation proportional to the change, following the maintenance guide. Review
Markdown directly for privacy: the release verifier audits public/build content,
not repository documentation. Report what changed, what was checked, results, and
remaining limitations honestly; do not describe deferred or unperformed checks as
passed.

Obtain authorization before expanding scope or staging, committing, pushing,
merging, dispatching or rerunning deployment, or publishing when authorization has
not already been granted. Existing session authorization remains sufficient for
the approved work; do not introduce repeated confirmation gates. Automated checks
do not grant authority to accept or publish a release.
